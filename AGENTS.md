## Guidelines
- domain model: use and update CONTEXT.md to build a mental model of the project and it's domain language
- architecture: hexagonal, deep modules, low coupling, high cohesion 
- git: branch per change, conventional commit after every meaningful change
- plan: decompose complex tasks into dependency graph and vertical slices
- code: use tech stack docs to following best practices
- docs: clean and concise wording, mermaid diagrams, progressive disclosure
